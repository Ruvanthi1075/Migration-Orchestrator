# migration/hybrid/

Everything for the Hybrid (PQC) stunnel cutover — guide
`QSMO_Implementation_Guide.docx` §8.2–§8.5. Kept entirely separate from
`migration/certs/` and `migration/stunnel_configs/`, which belong to
the Legacy classical baseline and the earlier Stage-1-classical-only
stunnel prototype respectively — never mix cert material or configs
across these three directories.

```
migration/hybrid/
  check_chain.sh         Layer-by-layer check of the chained stunnel
                          path. Run after starting osken-manager and
                          the shared server, before any migrate().
  gen_hybrid_certs.sh    Run this first. Generates hybrid-ca + controller
                          + one per-switch ML-DSA cert (guide §8.4).
  certs/                  (generated by gen_hybrid_certs.sh, gitignored)
  stunnel/
    server.conf            Shared controller-side stunnel config, TWO
                            chained services in one process:
                            [hybrid-controller] (PQC in on :16653) ->
                            plaintext :6660 -> [legacy-rewrap]
                            (classical TLS, Legacy switch cert) ->
                            OS-Ken :6653. OS-Ken cannot expose a
                            second listener, so it is left unchanged.
                            NOT auto-generated. Paths are absolute
                            (/home/sahana/Migration-Orchestrator/...);
                            sed them if your repo is elsewhere.
    client_<dpid>.conf     Auto-rendered per-switch by
                            migrate_link.py's _render_client_conf() the
                            first time that dpid is migrated. Do not
                            hand-write these -- they're regenerated
                            fresh (and idempotently reused) on every
                            migrate(dpid) call.
    logs/
      server.log            stunnel SERVER's own log (debug=6), both
                              chained services.
      client_<dpid>.log      Per-switch client log -- this is what
                              migrate_link.py's Stage 1 dry run parses
                              for a completed-handshake line
                              ("TLS connected: new session negotiated");
                              `curve` is restricted to X25519MLKEM768 on
                              both ends, so success == that group.
```

## Order of operations

1. `./gen_hybrid_certs.sh` (needs `/opt/openssl35/bin/openssl` with
   native ML-DSA support — see the script's own preflight check).
2. Confirm `stunnel/server.conf`'s absolute paths match this machine.
   The backend-port collision is resolved by the chained
   `[hybrid-controller]` -> `[legacy-rewrap]` design (see
   `docs/PORTS.md`); `migration/certs/` (from `gen_certs.sh`) must
   exist too, since `[legacy-rewrap]` uses the Legacy switch cert.
   Then `bash migration/hybrid/check_chain.sh` (with `osken-manager`
   and `stunnel migration/hybrid/stunnel/server.conf` running).
   Stop the manually started server before `migrate()` -- the
   executor starts and owns that process itself.
3. Confirm `stunnel` is on `PATH` (`which stunnel`). Live testing
   confirmed the system build already negotiates `X25519MLKEM768`
   correctly via the `curve` directive — no separate rebuilt binary
   is needed (an earlier draft of this project assumed otherwise; see
   `migrate_link.py`'s D2 design-decision note for the corrected
   story). Override `hybrid_stunnel_bin` only if a specific deployment
   genuinely needs a different binary.
4. Everything else (starting the server process, rendering and
   starting each switch's client, the dry-run group check, the live
   cutover) is driven automatically by
   `migrate_link.MigrationExecutor.migrate(dpid)` — see that file's
   module docstring for the full two-stage procedure.

## Testing without any of the above installed

`python3 migration/migrate_link.py` runs migrate_link.py's own
self-test suite against a fake command runner — it exercises every
branch of `migrate()` (full success, wrong negotiated group, missing
stunnel binary, Stage 2 timeout-and-revert, idempotent re-migrate of an
already-Hybrid switch) with no real Mininet/OVS/stunnel/OpenSSL on the
machine. Run this first; it should pass before attempting the real
live-system test in guide §11.
